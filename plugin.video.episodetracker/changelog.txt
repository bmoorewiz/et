v1.12.2
- Fixes Next Episodes coming up empty with "Something went wrong:
  unhashable type: 'dict'". Both sides of the resume-position lookup
  built a dictionary key straight out of Trakt's ids, so a single value
  in there that was an object rather than a number or a string raised on
  the lookup and took the entire list down with it.
- Values that cannot be a key are now skipped, costing at most the
  ability to match on that one id, and the resume decoration can no
  longer blank the list even if it fails some other way - the episodes
  matter more than the position markers on them.
- A crash row now opens the diagnostics upload instead of the settings
  dialog. The message alone never says which line raised.

v1.12.1
- Fixes shows not playing. Two TorBox timeouts benched it for five
  minutes, and with Real-Debrid expired there was nothing left: the next
  nineteen sources each failed in under a second against two services
  that were both out, and the queue was gone in ten seconds.
- A benched service now gets one trial request per bench, so a provider
  that comes back seconds later is used immediately instead of sitting
  out the rest of the five minutes.
- A provider outage stops the queue and names the service that is out.
  Nothing about a source changes an outage, so the remaining sources are
  left untried for when it is back rather than spent on a certainty.
- The failure message counts the sources actually tried, not the number
  queued.

v1.12.0
- Account credentials are kept in the add-on's own file as well as Kodi's
  settings, and put back whenever the settings copy has lost them. Kodi
  rewrites its settings file whole, so anything that disturbs it takes
  every credential at once - which is what happened. The TorBox API key
  in particular now survives an update, a settings wipe, and a schema
  that fails to load.
- Signing out still sticks: revoking a service drops its backup too, so a
  key you deliberately cleared is not resurrected on the next launch. The
  settings copy always wins while it has a value, so editing a key in the
  settings dialog behaves exactly as it looks.
- The update now snapshots credentials before extracting and restores
  after, and a test fails the build if a backed-up setting id is ever
  renamed or removed from the schema - which is the only way an update
  could still drop one.

v1.11.3
- Every message during a resolve now names the service actually being
  used. "Resolving with Real-Debrid..." was hardcoded and is the only
  thing on screen while sources are tried, so a TorBox-only install was
  told a dead provider was doing the work. It now names whichever
  services are configured.
- A debrid account problem is no longer headed "Authorize Real-Debrid",
  which blamed Real-Debrid for a TorBox failure, and "no debrid service

- Two settings that drive both providers were labelled Real-Debrid:
  the resolve timeout and the cache check.

v1.11.2
- A device that cannot save settings now says so. Kodi reports nothing
  when a setting write goes nowhere - a full or read-only profile fails
  in silence - so the add-on presented as signed out of every account
  with nothing on screen explaining why. Writes are now read back,
  authorizing an account that does not persist says exactly that instead
  of announcing success, and the main menu carries a one-line reason
  whenever an account looks unlinked.
- Diagnostics can be uploaded from the main menu. The one tool for
  diagnosing a broken settings dialog should not live only behind the

v1.11.1
- Fixes the hidden setting added in v1.11.0. It was the only setting in the
  add-on without a label, and it was written during ordinary browsing - in
  Kodi that rewrites the whole stored settings file, and lands in the
  settings dialog itself when one is open. The date of the last expiry
  reminder is bookkeeping, not a preference, so it now lives in the
  add-on's own cache and the setting is gone.
- Diagnostics now report whether stored settings are actually reaching the
  add-on. If a value is on disk but reads back empty, the schema did not
  load - which makes the add-on look signed out of everything and its
  settings dialog come up blank. Through the settings API alone that is
  indistinguishable from genuinely signing out; the report now says which.

v1.11.0
- A debrid service that can no longer serve is now stepped over
  automatically. When a Real-Debrid subscription lapses, TorBox simply
  takes over - the same in reverse - instead of every source failing
  through the dead one first. The add-on already knew the account had
  expired; nothing acted on it.
- If only one service is set up it is still tried, expired or not, because
  its real error is more use than silence.
- A subscription with three days or less left now says so, once a day, so
  a lapse is not a surprise - with a second service configured nothing
  visibly breaks when it happens.

v1.10.2
- Fixed TorBox rarely being used even when it had the torrent. Its cache
  check was being switched off for the whole session by a single failed
  account check, so no source was ever flagged as cached on TorBox and
  playback had no reason to try it first. The check now runs on its own -
  a bad key is reported by the check itself, without a separate lookup.
- The log now records what each service said about the cache, so "why is
  it never using TorBox" is answerable from a diagnostics upload.

v1.10.1
- A debrid service that stops answering is now set aside for a few minutes
  instead of being retried for every source. With the box offline, each of
  twelve sources was waiting out a 30-second timeout twice over, so a
  failed playback took twelve minutes; it now takes seconds.
- Network timeouts shortened. These are small requests, and a 30-second
  (Real-Debrid: 45-second) wait only ever delayed bad news.
- "TorBox did not accept the stored API key" is no longer shown when the
  real problem is the network. It now says TorBox could not be reached,
  which is the difference between checking your wifi and regenerating a
  key that was working fine.
- Whichever service is actually answering is tried first.
- The diagnostics report now includes the settings added since it was
  written - season packs, resume, play-next and the list options.

v1.10.0
- Next Episodes now shows what is left of anything you started and did not
  finish, e.g. "(26m left)", so you can tell at a glance whether there is
  time for it tonight.
- Those episodes are pinned to the top of the list, whatever sort order you
  have chosen. Turn it off with "Put part-watched episodes first".
- Skins that draw a progress bar on list items now get one, from the same
  position. Selecting the episode resumes it as before.
- The position is looked up fresh each time the list is opened rather than
  cached with it, because where you got to changes every time you stop
  watching and the next-up list does not.

v1.9.1
- Fixed episodes being marked watched half a minute in. Kodi does not know
  a stream's real length the instant playback starts - for a debrid stream
  it can report a few seconds until it has worked the file out - and 25
  seconds of a "30 second" episode looks like 83% watched. Progress is now
  ignored until the reported length is credible next to the runtime Trakt
  gives for the item.
- Nothing is reported to Trakt from a length that is not credible either.
  Trakt marks an item watched itself at 80%, so a bad percentage reaching
  it was a second route to the same problem.
- Crossing the watched threshold now has to hold for two checks in a row,
  so a single odd reading cannot mark a whole episode watched.
- A broken source that is only seconds long no longer counts as watched
  when it reaches its end.

v1.9.0
- "Browse seasons" on an episode's context menu, opening that show's
  seasons and every episode in them - so you can reach any episode of a
  show without searching for it again.
- Browsed episodes now show which ones you have already watched.
- "Mark watched up to here" on an episode's context menu, which marks
  every earlier episode of the show as watched in one go. For a show

- It tells you how many episodes it will mark before doing anything, and

v1.8.1
- Fixed backing out of a search dumping you on the main screen. Cancelling
  the keyboard handed Kodi an empty folder, which it had already committed
  to opening, so you landed on a blank screen instead of where you were.
  Cancelling now offers another go at the search, and Back from there
  behaves normally.
- The same blank screen could appear anywhere the add-on had nothing to
  show - no seasons, no sources, nothing part-watched, CocoScrapers not

  an empty list.
- A search that finds nothing no longer interrupts with a dialog you have
  to dismiss before you can try again.
- Any unexpected error now reports itself in the list you were looking at.
  Previously a crash left Kodi with no reply, and Kodi's own response to

  what "it errors out to the main screen" looked like.

v1.8.0
- Season packs. The add-on now also asks each provider for a season pack
  containing the episode you want, which for older or thinly-seeded shows
  is often the only cached source there is. Packs are labelled SEASON PACK
  in the list; the single episode is pulled out of them automatically. A
  Severance S01E03 search went from 36 sources to 78.
- Partial packs that stop before your episode are not offered.
- Fake releases are now remembered. Once a torrent has been shown to be a
  disguised executable, its hash is recorded and it stops appearing in
  source lists entirely.
- Sources too small to be the quality they claim are hidden. A 173-minute
  film advertised as 4K in 1.17 GB is a tenth of the bitrate that needs.
  The limits are deliberately generous, so small HEVC encodes are kept,
  and season packs are exempt.
- When playback fails, the message now says if a quality had sources that
  were never tried because its per-quality limit is 0 - the reason a
  CAM-only film fails with the default settings.
- Artwork. Posters, fanart, logos and episode stills now come from Trakt
  itself, so the lists and the player show the show rather than a generic
  icon. No extra account or API key involved.
- New "Continue Watching" menu listing everything you started and did not
  finish, with how far in you got, drawn from the same Trakt records the
  resume prompt uses.
- New "Refresh sources" on an episode or film's context menu, to re-scrape
  just that one item instead of clearing the whole cache.
- Next Episodes now shows how far through a series you are, e.g. (3/10).

v1.7.4
- Fixed episodes that have not aired yet appearing in Next Episodes.
  Trakt's progress endpoint often returns the next episode without an air
  date, and the filter treated a missing date as "assume it aired", so
  those episodes went straight through. It now also reads the show's
  aired/watched counts: once you have watched everything that has aired,
  whatever comes next by definition has not.
- When the air date is missing, the episode is now looked up directly so
  the list has a real date to work with. That also restores the runtime,
  without which the resume prompt could never work out a position, and
  the episode summary.
- The log now records how many unaired episodes were hidden, so this is
  visible in a diagnostics upload rather than invisible.

v1.7.3
- Episodes are now marked watched the moment they pass the threshold,
  while still playing, instead of waiting for you to press stop. Sitting
  through the credits or leaving an episode running used to leave it in
  Next Episodes until playback actually ended.
- The Next Episodes list is no longer cached by Kodi. Even once an
  episode was marked watched, backing out of the player redisplayed the
  copy Kodi had saved before playback started, so the episode you had
  just finished was still sitting there.
- A failed mark-watched is retried on the next check rather than lost,
  and gives up after three attempts so a Trakt outage cannot turn into a
  request every two seconds for the rest of the episode.

v1.7.2
- Fixed playback failing on fake releases. Some torrents contain a single
  large file named exactly like a real release but ending in .exe - it is
  malware, not a mislabelled video. The "fall back to the largest file"
  rule picked it, resolved it to a direct download link and handed it to
  Kodi, which could not play it. Executables, installers, scripts and
  shortcuts are now refused outright, so the add-on moves on to the next
  source instead of failing, and never resolves one to a download URL.
- Playback now uses the service that the source list says has the torrent
  cached. A source flagged [TB+] was still being sent to Real-Debrid
  first, so playback announced "Playing via Real-Debrid" and contradicted
  the flag you picked from. Whoever holds it cached is asked first; the
  other provider still gets a turn if that fails.
- The add-on's icon and fanart are now published alongside the zip in the
  repository, so the Kodi add-on browser shows artwork instead of a blank
  tile.

v1.7.1
- Added a proper test suite to the repository (366 tests, no dependencies
  beyond Python itself). It runs either side of every build, so a version
  bump can no longer ship a zip containing different code - which had
  happened twice - and a missing string or setting is caught before it
  reaches a screen.
- A source whose provider reports a non-numeric seeder count no longer
  discards the entire source list.
- Multi-part RAR releases (.r00, .r01) are now recognised as archives, so
  the reason a source will not play is reported accurately.
- Signing out of TorBox now also drops the cached account status, so a
  re-entered key is judged on its own merits rather than the old key's.

v1.7.0

- Pausing now tells Trakt, which is what creates that resume point in the

- Answering "no" to the resume prompt clears the old position, so

- When an episode finishes, Episode Tracker offers the next one from the

v1.6.0

- A short notification names the service when playback starts. Turn it

v1.5.2
- Fixed "Torrent contains no playable video file" rejecting torrents that
  were perfectly playable. The check only accepted 14 file extensions and
  only looked at one field for the file's name, so a release using .divx,
  .vob, .mts, .ogm, .m2v and others, or a provider reporting the name
  under a different key, was thrown away.
- The known extension list is much wider, several name fields are
  accepted, and if nothing matches by extension the largest file is used
  instead - an unrecognised container now costs a guess rather than the
  whole playback.
- Torrents holding only archives, and torrents with nothing big enough to
  be a video, are now reported as such instead of sharing one vague
  message.
- The torrent's file list is written to the log whenever selection is
  unusual, so a diagnostics upload shows exactly what was rejected.
- Both debrid providers now share this logic, so they behave identically.

v1.5.1
- "Upload logs for support" now posts to paste.kodi.tv, Kodi's own paste
  service, which accepts anonymous uploads. There is nothing to set up:
  press the button and share the link.
- The GitHub token setting has been removed. Uploading via GitHub needed a
  write-capable token, and a token shipped inside an add-on is readable by
  everyone who installs it, while a per-device one meant setup on every
  box. An anonymous paste needs neither.
- A token saved by an earlier version is still scrubbed from reports, so
  a leftover value cannot be uploaded.
- Redaction is unchanged and still covers Real-Debrid, TorBox, Trakt and

v1.5.0
- Added TorBox as a debrid provider alongside Real-Debrid. Enable it and
  paste your API key under Settings > Accounts.
- Both providers can be enabled at once. A source is tried against each in
  turn, which is worth doing because a torrent uncached on one is often
  cached on the other. The order is configurable.
- TorBox's cache check actually works, unlike Real-Debrid's deprecated
  one, so cached sources are genuinely flagged before you pick: [TB+] for
  TorBox, [RD+] for Real-Debrid, [Download] for uncached. Cached sources
  sort to the top.
- By default TorBox is only used for torrents it already has cached, so it
  never starts a download you would have to wait for. Turn off "Only use
  TorBox for cached torrents" to allow it.
- When every provider fails, each one's reason is reported rather than
  just the last.
- Diagnostics uploads include the TorBox settings and account state, with
  the API key redacted like every other credential.

v1.4.0
- New: Settings > Tools > "Upload logs to GitHub" gathers everything
  needed to diagnose a problem and puts it in a secret GitHub gist, then
  shows you the link to share.
  The report contains the add-on and Kodi versions, whether Trakt and
  Real-Debrid are authorized, the Real-Debrid account state, which
  CocoScrapers providers are enabled, every non-secret setting, and the
  last 512 KB of kodi.log.
- Credentials are removed before anything is uploaded. Kodi's log is
  written by Kodi and every other add-on, and Real-Debrid puts its token
  in the query string of every request, so tokens are present in older
  logs regardless of this add-on. The report is scrubbed by pattern and
  by exact match against the tokens this install actually holds, so a
  token still leaks nothing even where it appears with no key name.
  Secret settings are listed as "<set, redacted>", never by value.
- Uses your own GitHub token with the "gist" scope only, entered in
  Settings > Tools. No shared token is shipped: one embedded in a public
  add-on would hand write access to anyone who unzipped it.

v1.3.1
- Fixed items never being marked watched on Trakt. Playback tracking ran
  in a thread started by the plugin, but Kodi destroys the plugin process
  moments after it hands a URL over for playback and kills any thread
  still running in it - long before an episode reaches 80%. So the stop
  scrobble and the mark-watched never happened.
  Tracking now runs in a background service that lives as long as Kodi
  does. The plugin passes the item to it just before playback starts.
- Playing an item to the very end now counts as 100% rather than whatever
  the last progress sample happened to catch.
- A notification confirms when something has been marked watched.

  This needs Kodi restarted once after updating so the new service starts.

v1.3.0
- When a source fails to resolve, the fallback now works through a
  per-quality budget instead of a flat count: 5 x 4K, then 5 x 1080p,
  then 10 x 720p, then it gives up. Each tier is a setting under
  Settings > Playback, so the ladder can be reshaped.
- SD, CAM and screener results are excluded from the automatic fallback
  by default (their budget is 0). Set "SD sources to try" above zero to
  include them.
- The source you pick is always tried first and counts against its own
  tier's budget.
- Replaces the single "Maximum sources to try" setting, which is gone.
  It had to go rather than act as an extra ceiling: an existing install
  had it saved at 4, which would have silently truncated the new
  20-source ladder to 4 attempts.

v1.2.1
- Uncached sources are now given up on as soon as Real-Debrid starts
  actually downloading them, after a short grace period, instead of
  waiting out the whole resolve timeout. Real-Debrid only downloads a
  torrent that was not already cached, so continuing to wait could never
  succeed quickly. In testing this cut a run of 25 attempts from about
  8 minutes to about 2.5.
- New setting: "Give up on an uncached source after (seconds)", default
  4. A cached torrent passes through queued/downloading almost
  instantly, so the grace period keeps those from being abandoned by
  mistake; raise it if fast sources are being skipped.
- Real-Debrid resolve timeout default lowered from 20s to 15s. It now
  only bounds the genuinely slow cases, since uncached sources exit via
  the grace period.
- The "not cached" message now includes the seeder count.

v1.2.0
- Scraped sources now colour the quality badge by tier so the list is
  scannable at a glance: 4K gold, 1080p green, 720p blue, SD grey,
  screener orange, CAM red.
- The number of sources tried automatically when one fails to resolve is
  now up to 25 (was 4), and the setting range goes to 50. New installs
  default to 25; an existing install keeps its saved value, so raise it
  under Settings > Playback > Maximum sources to try.

v1.1.4
- The internal cache now sweeps expired rows instead of leaving them in
  place. Short-lived per-source Real-Debrid availability entries used to
  accumulate one dead row per source browsed and were never removed, so
  cache.db grew without bound on a long-running box. Expired rows are now
  purged opportunistically on write; live entries are untouched.

v1.1.3
- Next Episodes: an empty result is now cached for only 15 minutes
  instead of the full cache window. A genuinely caught-up account still
  isn\'t re-queried on every visit, but if every progress call fails at
  once the list recovers quickly instead of staying empty for hours.
- Scrobbling now binds to the file that is actually playing. Kodi keeps
  "is playing" true across back-to-back videos, so a monitor could
  otherwise attribute the next video\'s progress to the previous item and
  mark the wrong thing watched. It now stops as soon as the playing file
  changes.
- Internal: the Next Episodes list now builds its labels and metadata
  through the same helpers as the player, so the two cannot drift apart.

v1.1.2
- Fixed the misleading "Real-Debrid refused the magnet (check your
  account is active)" message. Adding a magnet discarded Real-Debrid's
  actual error and substituted a guess, which was wrong whenever the
  account was fine. Real-Debrid's own error is now reported, mapped
  through its official error_code table, with the code included.
- Recovers from two failures instead of reporting them:
    * "Torrent already active" (error 33) now reuses the transfer already
      in your account rather than failing. This happens as soon as you
      retry a source you have tried before.
    * "Too many active downloads" (error 21) now frees stalled transfer
      slots and retries once.
- Freeing transfer slots clears every stalled transfer when blocked,
  rather than only the single oldest one.
- A failed unrestrict reports Real-Debrid's reason too, instead of a
  generic "could not unrestrict".

v1.1.1
- The point at which something is marked watched on Trakt is now a
  setting, separately for episodes and movies. It was fixed at 80%, which
  is still the default, and the value is clamped to 1-100.
- Playback progress is now sampled every 5 seconds instead of 10, so the
  final reading is closer to where playback actually stopped - that value
  is what decides whether something counts as watched.
- The decision is logged either way, with the percentage reached and the
  threshold, so it is clear why something was or was not marked.

  Note: Trakt's own /scrobble/stop marks an item watched server-side at
  80% regardless of this setting. The threshold controls the add-on's
  additional /sync/history post, which is what makes the Next Episodes

v1.0.8
- Security fix: credentials could end up in the Kodi log. Real-Debrid
  takes its token as a URL query parameter, so any network error wrote
  the full URL - token included - into the log via the traceback. Kodi
  logs are routinely shared in forum posts and bug reports. Tokens,
  secrets, refresh tokens and authorization headers are now redacted
  before anything is written to the log.

v1.0.7
- The Real-Debrid account is verified before scraping. An expired or
  non-premium account now says so immediately instead of failing every
  source with an unhelpful error.
- Cache-check answers are stored locally (20 minutes by default,
  configurable) so moving around a source list does not re-query
  Real-Debrid and risk its rate limit.
- Availability is no longer queried at all for an account that cannot
  resolve anything.
- Cached sources are labelled [RD+] and uncached ones [RD Download],
  with cached sorted to the top.

v1.0.6
- Fixed "Could not resolve a playable link" on every source. Real-Debrid
  only fills in a torrent's download links once its status reaches
  "downloaded", but the add-on read the status once, immediately after
  adding the magnet, and gave up when links were absent. A new magnet is
  always still converting at that point, so this failed even for cached
  torrents. The status is now polled until the torrent is ready, with a
  configurable timeout (Settings > Playback).
- Playback failures now explain themselves instead of showing a generic
  message: not cached, dead torrent, magnet unreadable, flagged as a
  virus, no video file in the torrent, no file matching the episode, or
  the unrestrict failing.
- If a source fails, the next ranked source is tried automatically (up to
  4 by default, configurable, and can be turned off).
- Sources can be checked against the Real-Debrid cache before listing and
  are flagged and sorted accordingly. Real-Debrid has deprecated that
  endpoint, so when it returns nothing usable all sources are listed
  unflagged rather than being wrongly hidden.

v1.0.5
- Fixed scraping always finding no sources. Trakt returns year, tvdb and
  tmdb as numbers, and these were passed to CocoScrapers unchanged. The
  scrapers feed them to string operations - check_title() runs
  title.replace(year, '') - so the check failed for every candidate and
  every release was discarded. All scraper-facing values are now strings.
- Empty scrape results are no longer cached. One failed scrape used to
  hide sources for the whole cache window (6 hours by default), so a
  transient failure looked permanent.
- "No providers enabled in CocoScrapers" is now reported distinctly, with
  an offer to open its settings, instead of looking like "no sources
  found".
